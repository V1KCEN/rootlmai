# CHANGELOG

## [1.4.0] — Система порчи еды (FOOD SPOILAGE SYSTEM)

### Добавлено

- **Data Component `spoil_timestamp`** — хранит игровое время (в тиках), когда еда испортится.
- **Реестр сроков хранения** (`FoodSpoilageRegistry`) — сроки для всех продуктов из манифеста (хлеб 30, мясо 35/10, рыба 25/7, овощи 25/20, ягоды 15/20, яблоко 40, яйца 15, молоко 7, подозрительное рагу 2, сушёная ламинария 90).
- **Rotten Food** — собственный предмет (stack 64, питательность 0, насыщение 0, эффекты: голод 30с, тошнота 15с, отравление 10с).
- **Замена стака** — при порче весь стак заменяется на Rotten Food (количество сохраняется).
- **Проверка** — 1 раз в секунду на игрока, только по слотам его инвентаря.

### Изменено

- `ExampleMod.java` — регистрация `FoodSpoilageManager`, `FoodSpoilageData`, `FoodItems`, инициализация `FoodSpoilageRegistry`.

### Создано

- `rootimpact/food/FoodSpoilageData.java`
- `rootimpact/food/FoodSpoilageRegistry.java`
- `rootimpact/food/FoodSpoilageManager.java`
- `rootimpact/food/RottenFoodItem.java`
- `rootimpact/food/FoodItems.java`

### Известные ограничения

- Холодные биомы (скорость порчи ×0.33) не реализованы.
- Тыквенный пирог (stack max = 16) не реализован.

## [1.3.0] — Удаление Эндер-сундука (ENDER CHEST REMOVAL)

### Добавлено

- **Запрет крафта** — результат крафта эндер-сундука обнуляется.

- `ExampleMod.java` — регистрация `EnderChestHandler`.

### Создано

- `rootimpact/enderchest/EnderChestHandler.java` — обработчик удаления эндер-сундука.

## [1.2.0] — Система торговли жителей (VILLAGER TRADE SYSTEM)

### Добавлено

- **Запрет продажи алмазов** — алмаз (валюта) полностью запрещён в любой сделке (результат, стоимость A, стоимость B).
- **Запрет снаряжения выше каменного/кольчужного** — железная/алмазная/незеритовая броня, инструменты и оружие удалены из торговли.
- **Запрет зачарованных предметов и книг** — любой предмет с зачарованиями удалён из торговли.
- **Железо дороже** — железные слитки разрешены, но цена увеличена в 3 раза.
- **Отключение Hero of the Village** — скидки полностью отключены.
- **Отключение скидок зомби-жителя** — лечение работает, но не даёт скидок.

### Изменено

- `ExampleMod.java` — регистрация `TradeManager`, вызов `TradeFilter.apply()` в commonSetup.
- `examplemod.mixins.json` — добавлен `VillagerDiscountsMixin`.
- `RepairCountComponent.java` — исправлена депрекация `createDataComponents`.

### Создано

- `rootimpact/trade/TradeRules.java` — централизованные правила торговли
- `rootimpact/trade/FilteredItemListing.java` — обёртка ItemListing (фильтрация после генерации)
- `rootimpact/trade/TradeFilter.java` — модификация VillagerTrades.TRADES
- `rootimpact/trade/TradeManager.java` — менеджер торговли
- `mixin/VillagerDiscountsMixin.java` — отключение скидок

### Известные ограничения

- Wandering Trader не обработан (отдельный набор сделок).
- Лимиты не конфигурируются через RootImpactConfig.

## [1.1.0] — Доработка системы починки (REPAIR SYSTEM)

### Добавлено

- **Усиленная починка материалом** через наковальню:
  - Железный слиток — ×1.5 эффективности ремонта
  - Алмаз — ×1.25 эффективности ремонта
  - Незеритовый слиток — ×1.25 эффективности ремонта
  - Не влияет на repair_count
- **Тултип оставшихся ремонтов** — "Осталось ремонтов: X" (X = лимит − repair_count)
- **Обновлены лимиты ремонтов**:
  - Железная броня/оружие/инструменты — 4
  - Алмазная броня/оружие/инструменты — 2
  - Незеритовая броня/оружие/инструменты — 2
  - Луки/арбалеты/трезубцы — 2

### Изменено

- `RepairLimits.java` — обновлены лимиты, добавлены множители материалов
- `RepairHandler.java` — добавлена усиленная починка и тултип

### Известные ограничения

- Крестик в наковальне при достижении лимита не показывается (результат просто пустой).

## [1.0.0] — Система починки (REPAIR SYSTEM)

### Добавлено

- **Запрет ванильной починки через крафт** — объединение двух одинаковых предметов в верстаке (3×3) и сетке игрока (2×2) полностью отключено через Mixin на `RepairItemRecipe.matches()`.
- **Единственный способ починки — наковальня** — починка материалом, переименование и перенос зачарований работают через наковальню.
- **Запрет объединения двух одинаковых предметов в наковальне** — результат не появляется.
- **Data Component `examplemod:repair_count`** — хранит количество успешных ремонтов предмета, сериализуется автоматически.
- **Централизованный реестр лимитов ремонтов** (`RepairLimits`).
- **Увеличение repair_count на 1** за каждый успешный ремонт материалом (независимо от количества материалов).
- **Сообщение "Материал истощен, починка невозможна!"** при достижении лимита.

### Изменено

- `ExampleMod.java` — регистрация `RepairHandler` и `RepairCountComponent`.
- `examplemod.mixins.json` — добавлен `RepairItemRecipeMixin`.

### Создано

- `rootimpact/repair/RepairCountComponent.java`
- `rootimpact/repair/RepairLimits.java`
- `rootimpact/repair/RepairHandler.java`
- `mixin/RepairItemRecipeMixin.java`
